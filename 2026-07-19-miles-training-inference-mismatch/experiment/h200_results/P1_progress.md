## 途中所見1: mis_kl は並列度にほぼ不変 (TP1-TP8 で確認)

TP を 1 -> 2 -> 4 -> 8 と 8 倍振っても mis_kl は 0.000586 - 0.000710 の範囲
(max/min = **1.105 倍**) に収まり、しかも単調増加ではない (TP4 でいったん下がる)。
比較対象として slime 自身の run-to-run spread は 0.00053-0.00074 = **1.40 倍**なので、
掃引による変動はフレームワーク自身のばらつきより小さい。

つまり **trainer 側の並列分解は mismatch 源ではない**。「並列度を上げると mismatch が
増幅する」という仮説はこの範囲では否定される。実務的には「bf16 の良性床は
スケールアウトに対してロバスト」で、TP を上げるだけの理由で TIS を入れる必要はない。
**CP2 も効かなかった**。Fable は「CP なら attention の log-sum-exp 分割累積が効きうる」と
機構的に予測したが、TP4CP2 は +1.5% で TP4 単独 (-6.5%) との差もばらつきの範囲。
sequence 分割による attention の部分和統合は、少なくとも CP2 では mismatch を生まない。

intra-node セル 5 つの range は 0.000586 - 0.000710 = **1.21 倍**。参照値として
slime 自身の run-to-run ばらつきが 1.40 倍、KV fp8_e5m2 の増幅が 45 倍なので、
並列度の効果は「自身のノイズに埋もれる」水準で、量子化とは桁が違う。

残るは 2 ノードでしか取れない 2 セル: tp8pp2 (PP がノード境界を跨ぐ / ネガティブ
コントロール) と tp16 (TP の all-reduce が EFA を通る唯一の構成)。

## 途中所見3 (新発見): TP8 で ppo_kl の完全ゼロが崩れる

ppo_kl は TP1/TP2/TP4 では厳密に 0.0 だったが、**TP8 で初めて非ゼロ**になった。

| TP | ppo_kl |
|---|---|
| 1 / 2 / 4 | 0.0 (厳密) |
| 8 | **-1.58e-11** |

値は 1e-11 で、これは浮動小数点の丸め誤差そのもの。ppo_kl は
`old_log_probs - log_probs` で、同じ重み・同じトークンに対する 2 回のフォワードの差
なので、演算が決定的なら厳密に 0 になる。TP8 では reduction が 8 方向に分割され、
2 回のフォワードで加算順序が一致しなくなるため 0 から外れたと解釈できる。

実害はない (dropout アーティファクトの 0.30 とは 6 桁違う) が、
**「ppo_kl の厳密ゼロは並列度に依存する」という機構の直接証拠**である。
既存の結論「ppo_kl は train-mode dropout のアーティファクト」は変わらないが、
そこに「ただし TP を上げると reduction 順序差による 1e-11 級の floor が乗る」
という但し書きが付く。ppo_kl を「厳密に 0 かどうか」で診断に使う場合、
大並列構成では閾値を 1e-10 程度に置く必要がある。

## 途中所見2: weight sync の値は単一測定として扱えない (当初解釈を訂正)

当初「TP1 0.5s -> TP2 1.8s で TP 依存に 3.6 倍動く」と読んだが、これは不正確だった。
ドライバが `tail -1` で 1 つの値だけ拾っていたためで、実際には**同一 run 内でも
rank 間でばらつく**。

| セル | rank 間で観測された値 |
|---|---|
| tp1 | 0.5 (全 rank 一致) |
| tp2 | 1.2 / 1.6 / 1.8 |
| tp4 | 0.9 / 1.3 |

したがって表の weight_sync 列は「その run で観測された最大値付近」であり、
セル間比較には使えない。TP を上げると値が散る (TP1 は一致、TP2/TP4 は散る) 傾向自体は
実在しそうで、shard が細かくなり rank ごとの chunk 数と IPC 往復回数が変わることと
整合するが、断定はできない。

これは P3 の設計に直結する。P3 では (a) NUM_ROLLOUT を増やして各セルで weight sync を
複数回踏ませ、(b) 全 rank の値を集めて分布として扱い、(c) 初回 (接続確立込み) と
定常を分ける。単一測定で方式差やハード差を論じてはいけない。

なお B300 の既存実測 (colocated 1.5s / disaggregated 0.3s) も、この観点で
「全 rank の何回目の値なのか」を確認する必要がある。もし同様に最大値付近の
単一測定だったなら、5 倍差という結論自体の精度が問われる。
