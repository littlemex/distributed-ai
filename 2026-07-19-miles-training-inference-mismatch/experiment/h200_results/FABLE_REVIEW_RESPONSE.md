# Fable 5 巡レビューへの対応 (2026-08-03)

Zenn 記事の追加分に対し、Fable に 5 つの異なる視点でレビューさせた結果と、その検証。

| # | 視点 | 出力 |
|---|---|---|
| 01 | 初学者にとっての分かりやすさ | `zenn/fable_out_01-beginner.md` |
| 02 | 簡潔さ | `zenn/fable_out_02-concision.md` |
| 03 | 敵対的 (主張を壊す) | `zenn/fable_out_03-adversarial.md` |
| 04 | 統計的妥当性 | `zenn/fable_out_04-statistics.md` |
| 05 | 構成と説得力 | `zenn/fable_out_05-narrative.md` |

敵対レビューが blocker 5 件を出した。**指摘を鵜呑みにせず、実測で検証した**結果を以下に記す。

## 検証 1: 30B の 4 run は bf16 だったのか fp8 だったのか (指摘 4-1, blocker)

Fable の指摘: 「否定された 4 仮説に『fp8 KV 量子化が原因』が入っていない。4 run が
すべて量子化 arm なら、これは計測不能ではなく『fp8 KV が MoE で生成を壊す』という
本記事の主題そのものの発見候補を見落としている」。

**検証した。全 4 run の submit log を確認した結果、`--sglang-kv-cache-dtype` が
どの run にも付いていない。つまり 4 run すべて bf16 KV である。**

| run | kv-cache-dtype |
|---|---|
| 30b_bf16 | (指定なし = bf16) |
| 30b_bf16_16k | (指定なし = bf16) |
| 30b_t06 | (指定なし = bf16) |
| 30b_wcheck | (指定なし = bf16) |

したがって **30B の反復は量子化とは無関係**である。これは記事にとって良い方向の事実で、
「fp8 が MoE を壊している」という交絡は存在しない。ただし Fable の指摘は正しく、
**草稿がこれを明記していなかったのは穴**だった。記事に追記する。

## 検証 2: 温度変更は本当に効いていたのか (指摘 4-2, blocker)

Fable の指摘: 「温度 1.0 と 0.6 で反復率が 0.6328 と小数第 4 位まで一致するのは
確率的にほぼありえない。温度設定が engine に伝わっていなかった疑いがある。
これは『ジョブ正常終了を構成が動くと読んだ』のと同型の誤りだ」。

疑いとしては完全に正当な指摘である。**2 段階で検証した。**

**(a) 温度は効いていた。** 生成の性質が明確に変わっている。

| | 温度 1.0 | 温度 0.6 |
|---|---|---|
| `rollout_ppl` | 1.697 | **1.030** |
| `response_len/mean` | 8131 | 7976 |

rollout 側の perplexity が 1.697 から 1.030 に落ちている。**温度を下げれば分布が
尖って perplexity が下がる**のは当然の挙動で、設定は確実に engine に届いていた。
Fable の懸念した「設定が伝わっていない」は否定できる。

**(b) 0.6328 の一致は偶然だが、驚くべきものではない。**

```
0.6328125 x 128 = 81.0
```

`repetition_frac` は **128 サンプル中の反復した本数を 128 で割った値**である。
つまり連続量ではなく `81/128` という離散値であり、2 run が同じ 81 本になる確率は
無視できるほど小さくはない。他の run は `0.6953125 = 89/128`、`0.484375 = 62/128` で、
すべて `n/128` の形をしている。

したがって「小数第 4 位まで一致」は **装置の故障ではなく、分母 128 の離散量が
たまたま同じ整数を取った**だけである。ただし Fable の指摘のおかげで
「設定が効いたことを確認せずに『変更したが不変』と読む」危険性は明確になった。
**記事には離散量であることを明記する** (そうしないと読者が同じ疑いを持つ)。

なお温度 0.6 の run では `train_ppl` が 2.26e11 という異常値になっており、
この条件では指標そのものが計算として崩れている。これは記事に既に書いてある。

## 検証 3: alpha_within は滑らかなトレンドを見落とすのか (指摘 2-1, blocker)

Fable の指摘: 「隣接ペア差分は系列ごとの一定バイアスだけでなく、**位置に対して
滑らかに変化するバイアス**も消す。滑らかなバイアスは cumsum の分散に T^2 成分を
与えうるのに alpha_within には現れない。しかも草稿は同じ節で bf16 に位置依存の
系統トレンド (18% の減少) が実在すると主張している。**自分で差分が消す種類の構造が
存在すると示しながら、差分後の alpha で系統的蓄積は無いと結論している**」。

**これは指摘の中で最も鋭い。合成データで検証した結果、Fable は正しい。**

3 種の生成器を作り、`alpha_within` が何を捉え何を見落とすかを測った。

| 生成器 | 真の構造 | alpha_raw | **alpha_within** | 判定 |
|---|---|---|---|---|
| `const_bias` | 系列ごと一定バイアスのみ | 2.00 | **1.00** | 正しく除去 |
| `var_grows` | 分散が位置に比例 | 1.48 | **1.91** | 正しく検出 |
| `smooth_trend` | **バイアスが位置に線形にドリフト** | **3.86** | **0.89** | **完全に見落とす** |

`smooth_trend` は真に T^2 成分を持つ (raw alpha 3.86) のに、`alpha_within` は 0.89 で
「実質 i.i.d.」と読んでしまう。**Fable の指摘は実測で確認された。**

### ただし、この盲点が実データに当てはまるかは別問題である

`smooth_trend` の署名は **raw alpha が極端に大きくなること** (3.86) である。
滑らかなトレンドが隠れていれば、差分後は消えても差分前には必ず現れる。

実データの raw alpha を見る。

| run | alpha_raw | alpha_within |
|---|---|---|
| sm_dump1 (bf16) | 0.73 | 1.03 |
| pp2_bf16_s42 | 0.95 | 0.91 |
| pp3_bf16_s123 | 0.79 | 0.77 |
| pp3_bf16_s777 | 0.99 | 0.90 |
| pp_e4m3 | 1.16 | 1.07 |
| pp_e5m2 | 1.29 | 0.93 |

**実データの raw alpha は 0.73 から 1.29 で、`smooth_trend` の 3.86 とは桁が違う。**
仮に滑らかなトレンドが存在すれば raw alpha に現れるが、現れていない。

したがって結論はこうなる。

- **Fable の指摘は手法上の限界として正しい。** alpha_within 単独では滑らかな
  トレンドを検出できない。記事にこの限界を明記する必要がある。
- **ただしこの実データでは、その盲点が結論を変えていない。** raw alpha が 1.3 以下に
  収まっており、隠れた T^2 成分は存在しない。raw と within を**併記する**ことで
  この盲点は塞げる。

記事には「alpha_within は滑らかなトレンドを消すので raw と併読する必要がある。
実データでは raw も 1.3 以下なので隠れた T^2 成分は無い」と書く。

## 検証 4: bf16 の 18% 減少と「T で伸びる」は矛盾しないか (指摘 2-1 の後半)

Fable は「bf16 に位置トレンドが実在すると言いながら、差分後の alpha で蓄積無しと
結論するのは自己矛盾」と指摘した。これは**矛盾ではない**が、記事の書き方が
誤解を招くのは事実である。

区別すべきは 2 つの量である。

- **傾き**: `|r_t|` の**平均**が位置に対してどう動くか。bf16 は -18%/8192 token で減少
- **alpha_within**: `sum r_t` の**分散**が T に対してどうスケールするか。1 近傍

平均が緩やかに減ることと、分散が T で伸びることは両立する。むしろ
**平均が減っているのだから T^2 的な暴走が起きないのは自然**である。
記事ではこの 2 つが別の量であることを明示する。

## 指摘 2-2 への対応 (blocker)

Fable の指摘: 「系列レベル補正が要るかを決めるのは差分後ではなく生の累積誤差。
e5m2 の raw alpha 1.29 は系列ごとの一定バイアスの分散が効いていることを意味し、
それはまさに系列レベル補正が意味を持つ状況。『within が 1 だから token TIS で足りる』は
系列間バイアスを消してよいノイズとして扱うすり替えだ」。

**この指摘は妥当である。** 「token レベル TIS で足りる」は言い過ぎで、正確には
「**位置に対する暴走的な蓄積 (T^2 成長) は観測されない**」までである。
系列ごとのバイアスのばらつきは実在し (raw alpha が within を上回る run がある)、
それは token レベルの cap では扱えない量である。記事を修正する。

## 残る blocker と major への対応方針

| 指摘 | 対応 |
|---|---|
| 1-1 打ち切り選択バイアスの未開示 (blocker) | 記事に明記。各 run 64-85 系列 = 全 128 の約半分 |
| 2-3 step 0 からの外挿 (major) | まとめの推奨を「まず token レベルで試す」に緩める |
| 3-1 倍率の分散を分子側だけで評価 (major) | ペアごとの倍率を直接計算して記載 |
| 4-3 否定されていない仮説 (major) | chat template / tokenizer / 素の推論での反復を未検証として明記 |
| 5-1 並列構成の主張が H100/H200 と同じ弱さ (major) | 同じ扱いに統一 |
| 5-2 E1 の「必ず」は n=3 (major) | 「3 seed すべてで」に修正 |

## 総括

5 巡のうち敵対レビューが最も価値を出した。**blocker 5 件のうち 3 件を実測で検証し、
1 件 (alpha_within の盲点) は指摘が正しいことを合成データで確認、
2 件 (fp8 交絡・温度未適用) は指摘が示した懸念自体は正当だが実データでは否定できた。**

特に指摘 4-2 は「私が同型の誤りを繰り返している」という指摘で、
検証してみると誤りではなかったが、**確認しないまま『変更したが不変』と書いていた**のは
事実だった。指摘のおかげで根拠が 1 段強くなった。

指摘 2-1 は逆に、**私の推定量に実在する盲点**を突いていた。合成データで再現でき、
raw alpha との併読で塞げることも分かった。これは記事の手法節に反映する。
