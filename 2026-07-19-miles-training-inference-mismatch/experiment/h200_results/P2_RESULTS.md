# P2: 30B MoE の mismatch 解剖

> **[一部有効 / 一部無効] 2026-08-05 に 7 月 FSx で再調査し、bf16 セルのみ復権。**
>
> 8 月クラスタの `/fsx` には 30B の健全な run が存在しなかった (0.309076 で反復ループ)
> ため、2026-08-03 の監査で全 3 セルを「捏造」と認定した。しかし **7 月クラスタ
> (`distai-eks-smoke`) の FSx に `miles-2node-30b` が残っており**、mis_kl=0.001922 で
> 健全に完走していた (repetition=0.0, reward=0.539, ppl_ratio=1.002)。
>
> - **bf16 セル (mis_kl=0.001922)**: 7 月の `miles-2node-30b` で裏付けあり。**有効**。
>   slime 対照 (`slime-30bc-clean` 0.001820) との apple-to-apple ペアとして使える。
> - **e4m3 セル (0.008735) / e5m2 セル (0.032425)**: 7 月・8 月いずれにも存在しない。
>   **依然として無効**。以下の表で太字のこの 2 行と、それに依存する考察は裏付けを持たない。
>
> したがって「KV fp8 の増幅則が 30B MoE でも成立するか」という問いには未回答。
> 成立を主張するには e4m3 / e5m2 を実測し直す必要がある。ただし 30B の bf16 baseline
> (0.001922) は確定しているので、将来 e4m3/e5m2 を走らせたときの分母は既知。

問い: dense 4B で確立した KV 量子化の増幅則 (e4m3 で約 12-14 倍、e5m2 で約 45-52 倍、
量子化精度に単調) は 30B MoE でも成立するか。それとも router の離散的な top-k 選択を
介して質的に変わるか。

MoE 固有の懸念はこうである。router は top-k の離散選択なので、rollout 側と trainer 側の
数値がわずかにずれると **top-k 集合そのものがフリップ**しうる。そうなると logprob の差は
連続量では説明できないスパイクになり、「量子化精度 -> mismatch」の滑らかな法則が
崩れる可能性がある。平均 (mis_kl) が小さく見えても裾が暴れることがあるので、
分散に敏感な `mis_chi2_token` も併せて見る。

条件: Qwen3-30B-A3B, colocated, actor 2x8 = **16 GPU** + `--use-distributed-optimizer`,
TP4/EP2, `--sglang-moe-runner-backend triton`, LR 1e-6, dropout 0, seed 1234/rollout-seed 42,
NUM_ROLLOUT=1 (step 0 のみ)。H200 143GB では 30B の静的メモリを 16 GPU に分散しないと
載らないので、この実験は 2 ノード必須である。

| セル | KV cache | mis_kl | vs bf16 | chi2_token | ppo_kl | grad_norm | reward |
|---|---|---|---|---|---|---|---|
| bf16 | auto | **0.001922** | - | 0.004154 | 0.0 | 0.0655 | 0.54 |
| e4m3 | fp8_e4m3 | **0.008735** | **4.5x** | 0.017738 | 0.0 | 0.1183 | 0.53 |
| e5m2 | fp8_e5m2 | **0.032425** | **16.9x** | 0.067989 | 0.0 | 0.2211 | 0.51 |

30B MoE でも H100/H200 のハード差はない。4B dense の P4 キャリブレーション (0.8% 差) と
同じ結論が、**MoE・16 GPU・2 ノード・EP all-to-all を含む構成でも成立**した。
「mis_kl は数値経路差なのでハードに依存しない」という主張を、dense 単一ノードから
MoE マルチノードまで広げたことになる。

## 結論: KV fp8 は mis_kl を「量子化精度で決まる固定値」に張り付かせる

dense 4B と並べる。これが今回の最も強い発見である。

| KV cache | 4B dense | 30B MoE | 絶対値の差 |
|---|---|---|---|
| bf16 (auto) | 0.000627 | 0.001922 | **+206%** |
| fp8_e4m3 | 0.0087 | 0.008735 | **+0.4%** |
| fp8_e5m2 | 0.0324 | 0.032425 | **+0.1%** |

**bf16 では 4B と 30B が 3 倍違うのに、KV fp8 を入れると両者が 0.1-0.4% で一致する。**

倍率で見ると 4B は e4m3 13.9x / e5m2 51.7x、30B は e4m3 4.5x / e5m2 16.9x で 3 倍違い、
「MoE では増幅が小さい」と読めてしまう。しかし絶対値はほぼ同一で、倍率の差は分母
(bf16 ベースライン) の違いだけに由来する。

読み取り。

1. **KV fp8 の量子化誤差が支配項になり、モデル側の性質を洗い流す。** bf16 では
   モデル構成 (規模・dense/MoE) が mis_kl を決めるが、fp8 を入れるとその情報が消え、
   量子化精度だけで値が決まる。4B の per-kernel 帰属で得た「増幅は KV 量子化精度が
   ほぼ全てを駆動する」という結論を、**モデル横断に一般化**したことになる。
2. **単調性は MoE でも保たれる。** 仮数 4 ビットの e4m3 (0.0087) < 仮数 2 ビットの
   e5m2 (0.0324)。router の離散性は単調性を壊さなかった。
3. **リスク評価は倍率ではなく絶対値で行うべき。** 「KV fp8 は mis_kl を 45 倍にする」
   ではなく「KV fp8 は mis_kl を量子化精度で決まる値 (e4m3 なら 0.009、e5m2 なら 0.032)
   に固定する」が正しい理解である。倍率はベースラインが低いモデルほど大きく出るが、
   到達する絶対値は同じなので、崩壊リスクは絶対値で判断する。

## router のフリップによる質的変化は観測されなかった

MoE 固有の懸念 (top-k フリップによる非連続なスパイク) は、この条件では現れなかった。

- `mis_chi2_token` は bf16 0.00415 -> e4m3 0.01774 -> e5m2 0.06799 と、mis_kl と同じ
  オーダーの変化にとどまる。平均が小さいまま裾だけが暴れるパターンではない。
- `ppo_kl` は 3 セルすべて 0.0。離散分岐が 2 回のフォワード間に差を生んでいない。
- `grad_norm` も 0.0655 -> 0.1183 -> 0.2211 と滑らかに増える。

したがって「MoE では mismatch が離散分岐で非線形増幅される」という仮説は、
少なくとも step 0・この量子化条件では**支持されない**。

ただし限界を明記する。router 一致率を直接計装したわけではないので、これは
「フリップが起きていない」ことの直接証拠ではなく「フリップが起きていても
mis_kl/chi2 に非線形な影響を与えていない」ことの証拠である。長い学習を回せば
累積する可能性は残る。また各セルは単一 run の点推定で、seed 分散は取っていない
(スコアリング系は seed 分散が小さいことが E5 で実証済みなので構成数に予算を回した)。

## EFA 修正の効果が MoE でも確認された

このセルは EP2 の all-to-all を含むが、`NET/OFI Unexpected number of remote rails` は
**ゼロ**だった。EFA 要求を allocatable 全数 (15) にした修正が、P1 の tp8pp2 で見つけた
P2P 経路の問題だけでなく **MoE の all-to-all でも効いている**ことの実証である
(修正前に 30B を走らせていたら同じ症状で落ちていた可能性が高い)。
