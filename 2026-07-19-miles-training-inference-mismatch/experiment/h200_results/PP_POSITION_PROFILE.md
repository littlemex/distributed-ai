# 位置プロファイル: train/rollout の差は系列内で蓄積するか (4 seed)

> **データ裏付け: VERIFIED (二重確認済)** — 全 12 run。seed 1234: `sm_dump1` / `pp_e4m3` /
> `pp_e5m2`、seed 42: `pp2_*_s42`、seed 123: `pp3_*_s123`、seed 777: `pp3_*_s777`。
> 集約値は driver の `results.tsv` と TensorBoard event file の両方で一致。
> per-token ダンプは各 run 112-128 ファイル (`/fsx/dumps/<run>/`)。
> 判定定義は `DATA_STATUS.md`、照合は `python3 verify_results.py`。

問い: per-token の差 `r_t = train_logprob_t - rollout_logprob_t` は系列位置に対して
フラットか、それとも成長するか。これは arXiv:2602.01826 Thm 3.1 の O(T^2) 主張の
2 つの読み方を分ける。r_t がフラットなら系列レベルの累積誤差は T で伸び、
r_t が位置とともに成長するなら T^2 で伸びる。

因果 attention なので、8192 トークンの run で測ったプロファイルは、より長い run の
最初の 8192 位置と同じ量である。したがって **max_len を振る必要がなく**、
振れば入り込む交絡 (KV 予算、バッチ形状、chunked prefill 境界、内容分布、打ち切り率) も
一切入らない。

仮説: bf16 は数値経路のノイズなのでフラット。fp8 KV は毎トークンが量子化キャッシュに
attend するので誤差が蓄積し、傾きが正になる。

## 測定条件

Qwen3-4B dense, TP1/CP1, colocated 8 GPU, step 0 のみ (NUM_ROLLOUT=1), LR 1e-6,
dropout 0, `MIS_DUMP_EVERY=1`。各 run 128 系列、4 seed x 3 arm = 12 run。

seed は (train / rollout) の組で 1234/42、42/1234、123/456、777/888 の 4 通り。

**CP1・TP1 は意図的である。** ダンプは CP=1 でのみ書き、TP rank 0 からのみ書く。
CP>1 では Megatron が系列を 2*CP の zigzag チャンクに分割するので per-token の位置が
復元できない。TP>1 では全 TP rank が同一の logprob を持つため、そのまま集めると
同じ系列を TP 倍数え、bootstrap CI が sqrt(TP) 倍狭まる。判定はその CI に依存するので
偽陽性に直結する。どちらも計装側でガードしている。

## 結果: bf16 のみ有意に減少、fp8 は検出できない

絶対位置 (`prompt_len + response index`) に対する `|r|` の OLS 傾き。
区間は **seed 間**の標準誤差から t 分布 (df=3) で求めたもの。

| arm | 平均傾き (per token) | seed SE | 95% t 区間 | 判定 |
|---|---|---|---|---|
| bf16 | **-3.25e-07** | **3.55e-08** | [-4.38e-07, -2.12e-07] | **減少 (区間がゼロを除外)** |
| fp8_e4m3 | +1.23e-07 | 2.72e-07 | [-7.42e-07, +9.88e-07] | フラット |
| fp8_e5m2 | -7.61e-07 | 5.00e-07 | [-2.35e-06, +8.31e-07] | フラット |

seed ごとの内訳:

| arm | seed 1234 | seed 42 | seed 123 | seed 777 | 符号 |
|---|---|---|---|---|---|
| bf16 | -3.21e-07 | -3.76e-07 | -3.76e-07 | -2.26e-07 | **4/4 負で一貫** |
| fp8_e4m3 | **+6.31e-07** | -2.31e-08 | **-5.79e-07** | +4.63e-07 | 2 正 / 2 負 |
| fp8_e5m2 | +1.65e-08 | -1.18e-06 | **-1.98e-06** | +9.93e-08 | 2 正 / 2 負 |

**bf16 は 4 seed すべてで負に落ち、seed SE は 3.55e-08 と小さい。**
プールした区間もゼロを除外するので、「bf16 の位置プロファイルはわずかに減少する」は
実在する効果として言える (8192 トークンで平均 |r| の約 18% 減)。

**fp8 は seed ごとに符号が変わる。** e4m3 の seed SE 2.72e-07 は bf16 の 7.7 倍、
e5m2 の 5.00e-07 は 14 倍で、どちらもプールした区間がゼロを大きく跨ぐ。

したがって **fp8 KV による位置依存の誤差蓄積は、この測定精度では検出できない**。
存在しないことの証明ではなく検出力不足である。

## 単一 seed の結論を撤回した経緯 (この実験でいちばん重要な部分)

最初に seed 1234 だけを見たとき、次のように読んだ。

| arm | 傾き | 系列単位ブートストラップ CI (n=400) | 当時の読み |
|---|---|---|---|
| bf16 | -3.21e-07 | [-4.41e-07, -2.00e-07] | 減少 |
| fp8_e4m3 | +6.31e-07 | [+9.88e-08, +1.18e-06] | **蓄積** |

2 つの CI が重ならないので「量子化を入れると位置プロファイルの符号が反転する。
これは統計的に支持される」と結論した。**これは誤りだった。**

seed 42 で e4m3 は -2.31e-08 になった。**seed 1234 の CI はこの値を含まない。**
さらに seed 123 で -5.79e-07、seed 777 で +4.63e-07 と散った。
4 seed のうち +6.31e-07 は最も外れた 1 点だった。

原因は明確である。**系列単位クラスタブートストラップは「同じ run 内で系列を再抽出したら
どうなるか」しか測っていない。** rollout の内容分布そのものが seed で変わる効果は
その手続きに入っていない。したがって区間は構造的に狭すぎた。

`pool_seeds.py` はこの反省を実装したもので、seed 間の分散から区間を出す。
合成データ (既知の傾き +2.6e-06) で回復を確認済み。

## 分散スケーリング: 全 12 run で T^2 ではない

`Var[cumsum r]` が prefix 長 T に対してどうスケールするか。`alpha_within` は
隣接ペア差分を取った後の指数である。**この差分が厳密に消すのは系列ごとの一定オフセットだけ**で、
系列ごとに傾きの違う線形トレンドは半分残る (隣接差が定数 -b_j になるので
`Var(b_j) k^2/4` が残る。ノイズなしの純粋な線形トレンドで alpha_within 2.03 を実測確認)。
したがって alpha_within は「系列に沿って分散が増えるか」に答える量であり、
位置依存のスケールと系列間トレンドのばらつきを区別しない。alpha_raw と対で読む。

| arm | seed 1234 | seed 42 | seed 123 | seed 777 |
|---|---|---|---|---|
| bf16 | 1.03 | 0.91 | 0.77 | 0.90 |
| fp8_e4m3 | 1.07 | 0.76 | 1.08 | 1.08 |
| fp8_e5m2 | 0.93 | 0.95 | 0.88 | 1.09 |

**12 run すべてで alpha_within が 0.76-1.09** に収まり、2 には遠い。
傾きと違い、これは seed に対して安定している。

したがって **系列レベルの累積誤差は T で伸びており、O(T^2) ではない**。
arXiv:2602.01826 Thm 3.1 の O(T^2) は上界としては正しくても、この構成の実測では
その上界に張り付いていない。

実務的な含意: **位置に対する暴走的な蓄積 (T^2 成長) は観測されないので、
token レベルの TIS から試すべきである。** ただし「token レベルで足りる」と言い切るのは
行き過ぎで、alpha_raw が alpha_within を上回る run があり、系列ごとのばらつき自体は実在する。
それは token レベルの cap では扱えない量である。

## alpha_raw だけを見てはいけない

参考として seed 1234 の生の指数を記す。e5m2 では `alpha_raw` 1.29 が
`alpha_within` 0.93 を大きく上回る。生の分散は系列間のバイアス分散に押し上げられており、
これは位置に対する成長ではない。**alpha_raw だけを見て「T^2 に近い」と読むのは誤り**で、
この分解が無いと同じ罠に落ちる。

(Fable レビューの指摘で入れた分解。合成データでは、系列ごとの定数バイアスのみを持つ
生成器が alpha_raw 1.98 / alpha_within 0.90 になることを確認済み。)

## 副産物: mis_kl 自体の seed 分散

4 seed が揃ったので、集約値 `mis_kl` の seed 分散も分かった。

| arm | 平均 | min | max | CV | max/min |
|---|---|---|---|---|---|
| bf16 | 0.000595 | 0.000527 | 0.000625 | **7.8%** | 1.19 |
| fp8_e4m3 | 0.008149 | 0.007416 | 0.009360 | **11.3%** | 1.26 |
| fp8_e5m2 | 0.029509 | 0.025995 | 0.032907 | **10.7%** | 1.27 |

**これは以前の見積もりを訂正する。** `P2M_MODEL_SCALE.md` で「4B の seed 分散は
0.21-0.30%」と書いたが、それは別条件 (collapse 実験の step 0) の値だった。
この構成での実測は **CV 7.8-11.3%** である。

これはモデル規模軸の解釈に直接影響する。4B と 8B の e5m2 の差 26% は、
seed 分散 (CV 10.7%、max/min 1.27) と**同じオーダー**である。したがって
「fp8 の到達値はモデル依存」という主張は、**4B と 8B の 2 点では seed 分散と
区別できない**。`P2M_MODEL_SCALE.md` を訂正する必要がある。

## 限界

- 4 seed でも fp8 の傾きの符号は決められない。seed SE が bf16 の 8-14 倍あるため、
  仮に真の効果が bf16 と同程度の大きさなら、検出には 20 seed 以上を要する。
- 8192 トークンに到達した系列のみで比較している (各 run 64-85 系列)。
  打ち切り方向は 12 run で揃っているが、標本は各 run の全 128 系列の半分程度である。
- `prompt_len` の分布は全 run でほぼ同一 (median 147、範囲 100-243) なので、
  prompt オフセットによる交絡は小さい。
- log-log の点は prefix を共有する (T と 2T の cumsum は入れ子) ので、
  alpha の残差は独立でない。alpha は記述統計として扱う。
- 8192 での測定を長い系列に外挿する論法は、rollout エンジンの数値挙動
  (paged KV のブロック境界、chunked prefill) が max_len 設定に依存しない場合に厳密である。

## 教訓

単一 seed で CI がゼロを除外したことを「有意」と読んだのが誤りだった。
**系列単位ブートストラップは run 内のばらつきしか測らない。** rollout の内容が
seed で変わる実験では、seed 複製なしに符号の主張をしてはいけない。
2 本目の seed を取るコストは 1 セル 10 分で、これを省くと結論が反転する。

同時に、seed を 4 本まで増やしたことで **bf16 の減少は実在する効果として言える**ように
なった。seed 複製は主張を弱めるだけでなく、残った主張を強くする。

## 追加検証: 学習中も alpha_within は 1 近傍のままだった

これまでの位置プロファイルはすべて step 0 (optimizer step を踏む前) の測定で、
それが最大の限界だった。fp8 e5m2 で 14 step 学習させながら per-token ダンプを続け、
call 番号 (学習の進行とともに増える) で 4 分割して統計量を追った。

| call 範囲 | 系列数 | median 長 | 傾き \|r\| | alpha_raw | **alpha_within** |
|---|---|---|---|---|---|
| 2-53 | 243 | 8192 | 1.25e-06 | 1.35 | **0.932** |
| 54-105 | 224 | 8192 | 5.59e-07 | 1.32 | **0.972** |
| 106-157 | 218 | 8192 | 4.12e-07 | 1.52 | **0.955** |
| 158-210 | 216 | 8159 | 4.99e-09 | 1.34 | **1.01** |

**alpha_within は 0.93 から 1.01 の範囲で動かない。** step 0 の 12 run で得た
0.76-1.09 と同じ水準であり、学習が進んでも「誤差は T で伸びる」という結論は保たれた。
alpha_raw も 1.32-1.52 で、step 0 の 0.73-1.29 からわずかに上がるが 2 には遠い。

傾きは 1.25e-06 から 4.99e-09 へ単調に小さくなった。学習が進むと位置依存性が
弱まる方向だが、seed 1 本の測定なので符号・大きさの主張はしない
(seed 4 本でも fp8 の傾きは検出できなかった、という上記の結論が優先される)。

### ただしこの run は崩壊していない

重要な限界がある。この run の `mis_kl` は 14 step を通じて 0.0324 から 0.0283 で、
**上昇していない**。

```
0.0324 0.0282 0.0288 0.0267 0.0302 0.0271 0.0307
0.0271 0.0312 0.0274 0.0319 0.0279 0.0286 0.0283
```

崩壊実験 (`amplified_*`) が 30 step で 0.03 から 0.8-13.7 まで上がったのに対し、
この run は 14 step では立ち上がる前だった。したがってこの検証が示したのは

- **fp8 で増幅された水準 (mis_kl 約 0.03) を 14 step 維持しても alpha_within は 1 近傍**

までであって、

- **崩壊が進行した領域 (mis_kl 0.8-14) でも同じ構造か**

は依然として未検証である。崩壊まで追うには 30 step 必要で、そこまで回すと
1 セルあたり 2 時間を超える。step 0 限定という限界は「学習初期を含む」まで緩んだが、
完全には解消していない。
